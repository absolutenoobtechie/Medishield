# MediShield Model Context Protocol (MCP) Specification

This document defines the technical integration between **MediShield** and the **Model Context Protocol (MCP)**, specifying SDK usage, tool schemas, transport mechanisms, and the gateway mediation pattern.

---

## 1. Protocol Architecture & SDK

- **Specification Compliance:** Model Context Protocol (MCP) Standard (2024-11-05).
- **Official Python SDK:** `mcp>=1.9,<2.0` (Environment installed: `mcp 1.30.0`).
- **Transport Mechanism:** Standard Input / Standard Output (`stdio`) using JSON-RPC 2.0 framing.
- **Serialization Standard:** Pydantic v2 strict schema models (`extra="forbid"`).

```
┌────────────────────────────────────────────────────────┐
│                   MCP HOST / CLIENT                    │
│        (Claude Desktop, Cursor, Agent Runtime)         │
└───────────────────────────┬────────────────────────────┘
                            │ JSON-RPC 2.0 (stdio)
                            ▼
┌────────────────────────────────────────────────────────┐
│          MEDISHIELD MCP SERVER (server/mcp_server.py)  │
│          • Tool Declarations & Schemas                 │
│          • FastMCP / Server Stdio Dispatcher           │
└───────────────────────────┬────────────────────────────┘
                            │ ExecutionRequest
                            ▼
┌────────────────────────────────────────────────────────┐
│         MEDISHIELD GATEWAY (guard/gateway.py)          │
│         • Fail-Closed Verification Pipeline            │
│         • Cryptographic Intent Lock Matching           │
│         • Role & Destination Validation                │
└────────────────────────────────────────────────────────┘
```

## 2. Managed Clinical MCP Tools

MediShield defines 5 sensitive clinical MCP tools, each tied to an immutable security baseline:

### 2.1 Tool: `update_order` (Mutating)
Modifies an existing medication order in the simulated clinical backend. **Requires a valid clinician intent lock.**

- **Permitted Roles:** `agent`, `clinician`
- **Pinned Destination:** `backend://simulated-ehr/orders`
- **Tool Arguments Schema:**

```json
{
  "type": "object",
  "properties": {
    "request_id": {
      "type": "string",
      "description": "Unique request identifier generated by the client"
    },
    "actor_id": {
      "type": "string",
      "description": "Registered identifier of the calling agent (e.g. agent_1)"
    },
    "approval_id": {
      "type": "string",
      "description": "Cryptographic approval identifier issued by clinician"
    },
    "action": {
      "type": "object",
      "description": "Authoritative clinical action parameters",
      "properties": {
        "order_id": {"type": "string"},
        "patient_id": {"type": "string"},
        "medication_id": {"type": "string"},
        "dose": {"type": "string"},
        "units": {"type": "string"},
        "route": {"type": "string"},
        "frequency": {"type": "string"},
        "duration": {"type": ["string", "null"]}
      },
      "required": ["order_id", "patient_id", "medication_id", "dose", "units", "route", "frequency"]
    }
  },
  "required": ["request_id", "actor_id", "approval_id", "action"]
}
```

### 2.2 Tool: `read_patient_summary` (Read-Only)
Retrieves synthetic clinical summaries. Read-only operation.

- **Permitted Roles:** `agent`, `clinician`, `nurse`
- **Pinned Destination:** `backend://simulated-ehr/patients`
- **Tool Arguments:** `request_id: str`, `actor_id: str`, `patient_id: str`

### 2.3 Tool: `approve_action` (Administrative)
Generates and registers a cryptographic intent lock for one exact action. Restricted strictly to clinicians.

- **Permitted Roles:** `clinician`
- **Pinned Destination:** `backend://simulated-ehr/approvals`
- **Tool Arguments:** `approver_id: str`, `action: ProtectedAction`, `ttl_minutes: float`

### 2.4 Tool: `cancel_order` (Mutating)
Discontinues or cancels an active synthetic order.

- **Permitted Roles:** `clinician`
- **Pinned Destination:** `backend://simulated-ehr/orders`
- **Tool Arguments:** `request_id: str`, `actor_id: str`, `approval_id: str`, `order_id: str`

### 2.5 Tool: `dispense_simulated` (Mutating)
Triggers simulated pharmacy dispensing.

- **Permitted Roles:** `clinician`, `pharmacist`
- **Pinned Destination:** `backend://simulated-pharmacy/dispense`
- **Tool Arguments:** `request_id: str`, `actor_id: str`, `approval_id: str`, `order_id: str`

## 3. Gateway Mediation Pattern

When an MCP tool handler is triggered, it must never execute mutations directly. Instead, it delegates to `guard.gateway.verify_execution`:

```python
from guard.gateway import verify_execution
from guard.models import ExecutionRequest, ProtectedAction

async def handle_update_order(arguments: dict) -> dict:
    """Example MCP tool execution wrapper."""
    try:
        # 1. Parse and validate using strict Pydantic model
        action_data = arguments.get("action", {})
        action = ProtectedAction(
            order_id=action_data["order_id"],
            patient_id=action_data["patient_id"],
            medication_id=action_data["medication_id"],
            dose=str(action_data["dose"]),
            units=action_data["units"],
            route=action_data["route"],
            frequency=action_data["frequency"],
            duration=action_data.get("duration"),
        )
        
        request = ExecutionRequest(
            request_id=arguments["request_id"],
            actor_id=arguments["actor_id"],
            tool="update_order",
            approval_id=arguments["approval_id"],
            action=action,
        )

        # 2. Delegate to the authoritative security gateway
        decision = verify_execution(request)

        # 3. Format response based on gateway outcome
        if decision.decision == "allowed":
            return {
                "status": "success",
                "decision": "allowed",
                "rule": decision.rule,
                "message": decision.reason,
            }
        else:
            return {
                "status": "blocked",
                "decision": "blocked",
                "rule": decision.rule,
                "reason": decision.reason,
                "changed_fields": decision.changed_fields,
            }
    except Exception as exc:
        # Fail-closed error handling
        return {
            "status": "blocked",
            "decision": "blocked",
            "rule": "gateway_exception",
            "reason": f"Execution failed safely: {str(exc)}",
        }
```

### 4.2 Recommended Minimal FastMCP Implementation
For coordination with Codex, the smallest, safest FastMCP server binding pattern using `mcp.server.fastmcp` is:

```python
"""MediShield MCP Server reference implementation."""

from mcp.server.fastmcp import FastMCP
from guard.gateway import verify_execution
from guard.models import ExecutionRequest, ProtectedAction

mcp = FastMCP("MediShield-Gateway")

@mcp.tool()
def update_order(
    request_id: str,
    actor_id: str,
    approval_id: str,
    order_id: str,
    patient_id: str,
    medication_id: str,
    dose: str,
    units: str,
    route: str,
    frequency: str,
    duration: str | None = None,
) -> dict:
    """Update a medication order through the MediShield runtime security gateway."""
    action = ProtectedAction(
        order_id=order_id,
        patient_id=patient_id,
        medication_id=medication_id,
        dose=dose,
        units=units,
        route=route,
        frequency=frequency,
        duration=duration,
    )
    request = ExecutionRequest(
        request_id=request_id,
        actor_id=actor_id,
        tool="update_order",
        approval_id=approval_id,
        action=action,
    )
    decision = verify_execution(request)
    return decision.model_dump()

if __name__ == "__main__":
    mcp.run(transport="stdio")
```
